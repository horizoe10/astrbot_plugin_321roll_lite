# 321Roll Lite 玩法取舍清单

本文确定 321Roll Lite（AstrBot 群聊版）在纯文字交互下，对 321Roll 自定义房间全部玩法（世界引擎的 18 类通用玩法，加平台托管的 2 类）的保留、简化和删除方案，给出群聊指令草案，并确定运营边界、随附世界包和 WebUI 管理后台的方案。它是后续施工的范围依据；各项结论在“待确认事项”处理完之前都可以调整。

## 1. 依据

| 来源 | 位置与版本 | 用途 |
|---|---|---|
| 321Roll 平台 | `321Roll/source/src/party321`，提交 `24ebcd8` 加工作区（0.3.1 阶段 6A） | 20 个玩法开关、依赖、托管玩法、平台规则常量 |
| 世界引擎 | `321Roll/source/engine`，`party321-story-engine 1.0.0rc26` | `custom_plays.PLAYS` 动作目录（18 类通用玩法，共 140 个动作） |
| 世界格式 | `321roll.world-template/1`（`application/world_template.py`） | 属性、资源、技能、物品、职业、世界条目、规则 |
| AI 酒馆 | `astrbot_plugin_tavern` v0.12.0 发布包 | AstrBot 指令、群副本流程、WebUI 页面基线 |

Lite 沿用引擎的玩法键（如 `playInvestigation`）和动作名（如 `note_clue`）。“删除”和“暂缓”只表示 Lite 平台不受理该动作，不改引擎。

## 2. 取舍原则

1. **一条消息完成一个动作。** 参数最多三四个，复杂表单（议事、契印、机运盘布局）不进群聊。
2. **群聊是公开场合。** 依赖受众隔离的玩法，只有在平台能主动私聊时才开放，否则暂缓；隐藏设定（世界条目 `secret`）只给模型和后台看。
3. **主持类动作放后台。** 引擎里要求房主或主持人执行的动作（`OWNER_ACTIONS`），放进 WebUI 主持台或 `/团 主持`，玩家指令不暴露。
4. **与现有流程重叠的玩法不重复做。** 聚光灯请求由回合顺序承担，议事表决由协作表决承担，灵感由机运承担。
5. **保留本人确认。** 签署、接受困难、转变确认、进入结局这些“本人决定”的动作照常保留，它们在群聊里就是一句短指令。
6. **一次交付。** 总表中标为“本期”的玩法在同一版本交付；暂缓项有明确的重开条件。
7. **不接入运营。** 只做文字玩法，不做成长、档案、成就、货币等运营功能，见第 7 节。

## 4. 指令通则

### 4.1 前缀与格式

- 主前缀为 `/团`，兼容全角 `／团`。
- 格式：`/团 <玩法词> [子动作] [引用…] [选项…] [标题：]正文 [属性 难度]`。
- 高频指令设短写：`/团 选 A`、`/团 投 A`、`/团 搜查 …`。

### 4.2 记录引用

每个房间的玩法记录（线索、假设、证词、交涉、冲突、计划等）共用一条自增编号，写作 `#12`。每条回执都附上新记录的编号。指令声明了期望的记录类别，编号类别不符时拒绝并说明。`/团 记录 [类别]` 列出当前未结记录。

### 4.3 检定

检定写在句末方括号内：`[感知 困难]`。属性用本世界属性名，难度为 简单 / 标准 / 困难 / 极难，对应世界规则 `rules.difficulties`。省略方括号时，由引擎给出检定建议，平台用世界默认难度 `rules.dc`。骰点由平台公平随机源产生，先持久化再交给模型续写。

### 4.4 文本与选项

- 需要标题的动作按第一个冒号拆分：`怀表停在三点：表盘内侧刻着一个名字`。没有冒号时，取正文首句做标题。
- 固定选项用短中文词，例如 亲见 / 听说、支持 / 反驳、采纳 / 否定。
- 指名角色用平台 @ 或角色名。

### 4.5 回执

回执合并为一条消息，包括记录编号、检定结果、状态变化和下一步提示。可见性规则：

- 世界条目的隐藏内容（`secret`）不出现在群聊里，只进入模型上下文和后台。
- 主动私聊失败时，沿用 tavern 的“下次事件补发 / 仅后台 / 丢弃”策略。

## 5. 逐类明细

“保留”指 Lite 首次开放即受理的动作；“暂缓”指数据模型预留，后续按需开放；“删除”指 Lite 不做。

### 5.1 世界与行动（托管）

| 能力 | 来源 | 指令草案 |
|---|---|---|
| 选择本轮选项（1–4 个候选，A–D） | 平台托管回合 | `/团 选 A [补充演绎]` |
| 自由描述行动（世界 `rules.mode` 为 `hybrid` 或 `dialogue_only`） | 平台托管回合 | `/团 行动 <描述> [属性 难度]` |
| 检定建议与原骰 | 引擎 `resolution_check` + 平台 | 自动，回执展示骰点和档位 |
| 超时自动选择 | 引擎 `timeout_ranking` 只评风险，平台选风险最低者 | 自动；`/团 倒计时` 查看剩余时间 |
| 跳过、强制下一位、重整选项 | tavern 0.12.0 | `/团 跳过`；主持：`/团 强制下一位`、`/团 重整选项` |

删除：tavern 的“灵感 / 灵感重投”，优势和重投由机运承担。

### 5.15 暂缓与删除

- **私人并行阶段、合法汇合（暂缓，条件开放）**：受众隔离在公开群里做不到。只有平台实测支持主动私聊，并且后台开启“私聊投递”时才开放：`open_phase` 在群里发起，`phase_check` 和 `phase_note` 在私聊中执行，`ready_to_regroup` 和 `regroup` 回到群里。不支持的平台上，这两个开关保持关闭并显示原因。
- **闪回准备（暂缓）**：依赖行动计划的步骤和房主复核，等行动计划的暂缓项开放后再评估。
- **整备（删除）**：物资领取和工具借还，由世界格式的 `items`（含 `uses` 和 `consume`）以及 `resources` 承担。

## 7. 不接入运营

Lite 作为开源项目只做文字玩法，不接入任何运营类功能（2026-10-07 确定）。不做的内容：

- **角色成长**：房间奖励池（321Roll `room_rewards`）、训练项目带来的属性提升（`claim_training`）、引擎成长轨道（`character.progression`）。
- **账号层**：旅人档案、账号经验与等级、成就。
- **跨房间角色延续**：角色只属于一个房间，完结后随房间归档。
- **321Roll 经济与社交**：自然旅币、钱包、商城、好友、主页等。

玩法内的数值变化照常保留，它们是世界规则的一部分，不算成长，故事结束即止。包括：失败代价扣资源、休整回复资源、物品的次数与消耗、技能和物品的检定修正。“转变与传承”只记录叙事上的永久变化，不改动数值，作为文字玩法保留。

## 11. 0.1.0 实现记录

0.1.0 已实现本期范围（第 3 节标为“本期”的 16 个玩法键）。以下几处与前文的草案不同，以本节为准：

1. **交锋的“稳妥”**：引擎要求先“争取有利位置”才能稳妥出手，而该动作暂缓，所以只开放 `冒险` 和 `孤注`。`冒险` 的计分与普通交锋相同（成败各 1 分），回执只介绍 `孤注`（成败各 2 分）；不写风险档就是普通交锋。
2. **合力险关**：Lite 没有世界时钟，失守代价只能是伤势（作用于世界规则的失败资源）。立险关写成一行八项：`/团 主持 险关 标题｜局面｜第一路=属性,属性｜第二路=属性｜难度｜人数上限｜伤害｜过关后确立的事实`。立险关的主持人需要已入座，并默认守第一路。
3. **重整选项**：改为主持人手动设定，`/团 主持 选项 一｜二｜三`；另有 `/团 主持 推进` 让模型推进一步并给出新选项。
4. **开团权限**：`/团 开启` 只限管理员；开团者成为主持人。主持人或管理员可以使用主持类指令。
5. **检定写法**：托管行动（`/团 行动`）由模型判断是否需要检定；引擎玩法里需要检定的动作（搜查、追问、出示、交涉理由、争取态度、交锋、执行、推进项目）必须在句末写 `[属性 难度]`，因为引擎玩法不提供检定建议。
6. **预设结局**：`/团 结局` 会列出世界包预设的结局及达成条件作为参考，这些结局也写进了交给模型的世界简介；分支仍由玩家提出、全员支持后进入。
7. **集体事件**：默认每 3 轮自动触发一次（至少 2 名在场玩家，后台可改为 0–20 轮），主持人也可以手动发起。投票 2 分钟截止，全员投完立即结算；平票时以主持人的票为准。
8. **新增指令**：`/团 记录 [分类]` 列出玩法记录及编号，`/团 查看 #编号` 查看详情，`/团 回顾 [1-5]` 回顾最近剧情，`/团 主持 重试` 重新生成失败的正文，`/团 主持 换幕` 进入下一幕，`/团 主持 事件频率` 调整集体事件间隔。
9. **WebUI**：七个页面与 9.2 节一致。团桌详情里的主持操作以管理员身份执行对应的 `/团` 指令，回执推送到群里。
10. **消息样式**：所有推送由 `roll_lite/messages.py` 统一排版，按全局开关输出 Markdown 或纯文本。不支持 Markdown 的平台（OneBot 等）自动用纯文本；QQ 官方拒收 Markdown 时立即改发纯文本，并记住该平台。一轮行动按“个人状态 → 故事正文 → 行动选项”分段发送，间隔 0–3 秒可调，也可以合并为一条。三段各有一个转图片开关，用 AstrBot 文转图渲染，失败时改发文字。OneBot 用真实 @，其他平台在文字前加“@昵称”。符号克制（▰▱ ●○ ■□ 〔〕 ▸），不用 emoji。
11. **自定义世界**：预设世界只读，可以“复制为自定义世界”后修改。编辑器分七步：基本信息（封面字与配色、标题、世界观、开场、风格、主持要点、边界）、规则（属性、预算、资源、四档难度、人数、行动方式、技能栏位、失败代价与休整）、技能与物品、职业（属性分配与技能）、设定条目（含开场起点）、幕与结局、检查与保存。每步实时按世界格式校验并在步骤条上标出问题数；保存前再由世界引擎编译一次。未保存的修改自动留在本机草稿里。导出文件格式为 `321roll-lite.world-bundle/1`（一个 JSON 同时包含 `pack` 与 `presentation`），可以在导入页原样导回；导入页也接受 321Roll 的 `pack.json` 加可选 `presentation.json`。新建时编号不能与已有世界重复；覆盖已有自定义世界时版本号自动加一，已开的团桌继续使用开团时的快照。封面字和配色存放在 `presentation.cover`。
12. **删减（2026-10-07）**：不适合纯文字聊天的三项从 Lite 删除：合力险关（`form_joint` / `join_joint` / `roll_joint` / `settle_joint`，原 `/团 主持 险关`、`/团 险关`、`/团 守`）；神谕灵感表（`configure_oracle` / `consult_oracle`，原 `/团 主持 神谕表`、`/团 神谕 抽`），保留是非神谕；传承（转变的 `legacy` 形式），保留转变。理由：险关要一条八段指令立题再分两路认领掷骰，灵感表要主持人逐条录入表格，传承要提出者、本人、继承者三方依次确认，在群聊里都难以顺畅完成。

20. **主持人工具（2026-10-07）**：补齐主持人与管理员的权限，指名玩家可写角色名、昵称、`/团 阵容` 座位序号或 @ 对方。
    - 节奏：`/团 主持 轮到` 把当前回合交给指定玩家；`/团 主持 顺序` 查看或重排行动顺序；`/团 主持 回退` 恢复到最近一次行动结算前（每次结算和主持推进前自动留一份记录，存在 saves 表、`created_by=auto`，最多 5 份，不占 20 个手动存档名额，用一次删一份）；`/团 主持 表决时限 [1–30|默认]` 按桌设置表决截止时间，进行中的表决不变。
    - 裁定：`/团 主持 检定 角色 属性 难度 [受伤] [理由]` 由平台掷骰并写入时间线（kind=check，下一段正文可见）；带“受伤”且失败时，按世界规则的 harm 代价进入调整队列。`/团 主持 调整` 在聊天里提交与后台相同的调整（资源、物品、技能、次数、态度），下一回合正文写完后生效，可列出与撤销，允许在私聊使用。`/团 主持 指引` 也改为可在私聊使用。
    - 正文：`/团 主持 篇幅 简洁|均衡|长篇|默认` 把引擎的 `321roll-hosted-narrative-policy/2.0.0` 加入叙事上下文（字数由引擎严格校验）；只设 `/团 主持 文风` 而不设篇幅时，比例与风格作为一条主持要求写进近况，不触发字数校验。`/团 主持 审稿 开` 后，正文进入 `review` 状态并私发主持人，`/团 主持 发布` 提交，`/团 主持 重写 [意见]` 带意见重新生成；开启前需要主持人私聊过 bot（插件记住每位用户最近一次私聊的会话）。
    - 席位：`/团 主持 交棒`（管理员立即生效，主持人发出邀请，对方 `/团 接棒` 或 `/团 拒绝接棒`）；`/团 主持 移出`（不能移出主持人，被请离者进入名单，`/团 主持 放行` 后才能再入座）；`/团 主持 暂离`、`/团 主持 返回`；`/团 主持 入座 关|开`；`/团 主持 退回`（清空角色，玩家重新 `/团 选职业`，轮到他的回合自动交给下一位）。
    - 私聊：主持人没有入座也可以在私聊里使用允许私聊的主持指令。
    - 后台：主持操作新增篇幅、文风、审稿、回退、要求检定、表决时限、行动顺序、入座开关、放行；席位卡上有轮到、暂离/返回、退回、交棒、请离按钮；审稿草稿显示在“此刻”里，可直接发布或重写；操作面板底部列出本桌当前的篇幅、文风、审稿、入座、表决时限、可回退步数、待接棒和被请离名单。
21. **模型输出兼容（2026-10-07）**：DeepSeek 经 AstrBot 调用时没有严格结构化输出，常见“progress 写成 {}”“facts 照抄 fact_ref”“多出 annotations”，引擎按字段集合严格校验后报 `brief_start.fields_invalid`（这个校验函数定义在开场模块里，回合正文也复用它）。桥接层新增 `engine/conform.py`：按展示给模型的同一份 Schema 删除封闭对象里的多余字段，缺失字段只补 Schema 允许的空值（null、空列表、枚举里的空字符串），不补写正文、选项或数值；修正记录写入 `model_calls.note`。仍有问题时逐字段列出（如“progress 缺少字段 goal”），写入被拒调用的 `error` 和下一次重试的修复提示；失败提示里的原因改为第一条具体问题。提示词补充“可为 null 的键不要省略”和各对象的字段清单。后台“运行”页显示自动修正次数，失败记录附带修正内容。
