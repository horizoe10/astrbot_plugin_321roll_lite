# 世界包制作教程

世界包就是一个可以开团的故事世界：规则（属性、资源、难度）、角色（职业、技能、物品）、设定（地点、人物、线索）、故事节奏（幕与结局），再加上可选的场景图。做好的世界包可以自己用，也可以打成安装包分享给别人，或者发布到 GitHub 上，让别人在“世界市场”里一键安装。

这篇教程带你从模板开始做出一个世界包。每个字段的准确含义和限制见 [世界包规范](WORLD_PACK_SPEC.md)。

## 选一种做法

| 做法 | 适合 | 能否配图 |
|---|---|---|
| 后台编辑器 | 第一次做，想边填边看效果 | 只能做纯文本世界 |
| 从模板改 JSON | 文字量大、想用文本编辑器和 Git 管理 | 可以 |
| 两者结合 | 先在编辑器里写好，导出后再配图打包 | 可以 |

后台编辑器在“世界 → 新建世界 → 从空白开始”，七个步骤会逐项提示还缺什么，保存后就能开团，也能在详情页“导出安装包”分享给别人。下面主要讲第二种做法，它能做出带场景图、可以上架世界市场的完整安装包。

## 1. 复制模板

插件目录里的 `worlds/_template/` 是一个可以直接开团的小世界“雾港灯塔”，每个字段都填了示例。把整个文件夹复制到插件目录外面（例如 `D:/my-worlds/fog-harbor/`），以后都在副本上改。

```text
fog-harbor/
├── pack.json           规则、角色和设定（必需）
├── presentation.json   幕、地点、结局和封面（建议）
└── images/             场景图（可选，没有就是纯文本世界）
```

用支持 UTF-8 的编辑器打开 JSON 文件，例如 VS Code。改完随时可以按第 8 步校验。

## 2. 起名字和编号

打开 `pack.json`，先改这三项：

- `id`：世界的编号，安装、更新都靠它识别。用小写字母、数字和 `-`，建议带上你的名字做前缀，例如 `alice.fog-harbor`，避免和别人撞号。发布后不要再改。
- `title`：写成“主标题 · 副标题”，后台和群聊会分开显示这两部分。例如 `雾港灯塔 · 无人看守的灯，昨夜亮了`。
- `revision`：版本号，从 1 开始。以后每发布一次新内容就加 1。

同时把 `presentation.json` 里的 `pack` 改成同一个 id。

## 3. 写世界观和开场

| 字段 | 谁能看到 | 怎么写 |
|---|---|---|
| `worldview` | 只给 AI | 世界的基本事实：在哪、什么年代、有哪些势力、什么规矩 |
| `seed` | 开团时发到群里 | 开场的那一幕，要有一个让人想追下去的钩子 |
| `style` | 只给 AI | 文风和基调，一两句话 |
| `boundaries` | 只给 AI | 不写什么，例如血腥细节 |
| `guidance` | 只给 AI | 真相、伏笔、每一幕的节奏建议 |

AI 每轮都会读到世界观、主持要点、全部设定条目和结局条件，这些内容合在一起最多 6000 字，超出的部分会被截掉。所以世界观写骨架就够了，细节放进设定条目，总量控制在 4000 字左右比较稳妥。

## 4. 定规则

模板里的规则是常用的一套，第一次做可以原样保留：

- 五项属性，每项 6–16，职业属性加起来等于 `budget`（55）。
- 检定加值 = ⌊(属性 − 10) ÷ 2⌋，属性 6 是 −2，16 是 +3。
- 四档难度：简单 8、标准 12、困难 15、极难 18。玩家掷 d20 加上加值，达到难度就成功。
- 两种资源：体力（检定失败扣 1，休整回 3）和心神。

想换成自己世界的说法，改 `name` 就行，例如把“口才”改成“交涉”。改 `id` 时要同步修改所有引用它的地方（职业的属性分配、技能的 `attribute`）。

`rules.mode` 决定玩家怎么行动：`hybrid` 是选项加自由行动，`choice_only` 只给选项，`dialogue_only` 只能自由行动。

## 5. 技能和物品

技能属于职业，物品每个角色开局都带。两者字段相同：

- `attribute` + `modifier`：检定用这项属性时，加上这个加值。玩家行动时写 `[用 技能名]` 就会算进去。
- `cost` / `gain`：使用时扣掉或恢复某种资源。
- `uses` + `reset`：可用次数（0 为不限）和什么时候回满（`scene` 每幕、`rest` 休整后、`never` 不恢复）。
- 物品另有 `initial`（开局几件）和 `consume`（每用一次少几件）。

数值上的参考：普通技能 +2，每幕 2 次；+3 的技能最好带一点代价（消耗资源或只能用一次）；不需要检定、直接回血的技能把 `attribute` 留空、`modifier` 设 0。

## 6. 职业

每个职业给全部属性分配点数，总和必须等于 `budget`；技能数量不超过 `rules.skillSlots`。三到六个职业比较合适，最好每个职业都有明显擅长和明显不擅长的事，这样队伍里才会分工。

## 7. 设定条目与开场

`entries` 是世界里的地区、地点、势力、人物、目标和线索。

- `public: true` 的条目玩家能查到；`false` 的只有 AI 知道，适合藏起来的势力和关键线索。
- `summary` 是公开描述，不要剧透；`secret` 写真相，AI 会照着它安排剧情，但不会直接说出来。
- `links` 把相关条目连起来，帮助 AI 理解关系。

`initial` 是开场：地点、时间、局面，`links` 只能连公开条目。

## 8. 幕和结局

`presentation.json` 决定故事的节奏：

- `acts`：每一幕的编号、标题和一句引言。主持人用 `/团 主持 换幕` 推进，换幕时群里会显示新一幕的标题和引言。三到五幕比较合适。
- `endings`：可能的结局和达成条件。AI 会朝这些方向收束故事，所以条件要写清楚、彼此区分开。
- `places`：给重要地点配名字、别名和场景图。
- `cover`：封面用的一两个字和一种配色（`ink` 墨蓝、`ember` 余烬、`neon` 霓紫、`jade` 青玉、`wine` 酒红、`slate` 石灰）。

后台世界详情页会把幕和结局默认折叠，避免剧透。

## 9. 校验

纯文本世界最快的校验方法是导入后台：打开“世界 → 导入世界文件”，选择 `pack.json`，在“另附 presentation.json”里选上呈现文件，点“校验”。校验会实际编译一次规则，报错会写明哪个字段有问题。通过后可以直接导入试玩。

要配图或者发布到市场，用下一步的打包命令，它会做同样的校验。

## 10. 配场景图（可选）

在世界文件夹里建 `images/`，按图片编号命名：

| 文件 | 用在哪里 |
|---|---|
| `cover.webp` | 封面。有图片时必须有它，世界市场的预览图也由它生成 |
| `act-1.webp`、`act-2.webp`… | 每一幕的横幅，群聊图片卡片在这一幕时显示 |
| `place-<条目 id>.webp` | 地点图，显示在后台场景图里 |
| `ending-<结局 id>.webp` | 结局图，显示在后台场景图里 |

支持 webp、png、jpg。建议用 16:9、宽 1280 像素以上的图，打包时会统一缩到 1280 宽并转成 WebP。如果 `presentation.json` 里的幕、地点或结局写了 `image`，就用那个名字找文件；没写的按上表的默认名字找，找不到就不配图。几处想用同一张图时，在 `shared` 里写 `{"place-tide-inn": "act-2"}` 这样的对照，就不用重复放文件。

安装包里的图片会合成一个混淆过的文件，解压后不能直接预览，玩家翻文件也不会被剧透。

## 11. 打包

在插件目录（含 `roll_lite/` 和 `vendor/` 的那一层）打开命令行，运行：

```bash
pip install pillow        # 只需一次，用于处理图片；AstrBot 的环境里通常已经有了
python -X utf8 -m roll_lite.worlds.make D:/my-worlds/fog-harbor --out D:/my-market --name 爱丽丝的世界
```

成功后输出目录是这样的：

```text
my-market/
├── index.json                         世界市场读取的索引
├── packs/alice.fog-harbor-r1.zip      安装包
└── previews/alice.fog-harbor-r1.webp  市场卡片上的预览图（有封面图时）
```

多个世界可以打包到同一个输出目录，`index.json` 会保留已有的条目。

只想分享给朋友的话，把 zip 发过去就行，对方在“世界 → 世界市场 → 上传安装包”里安装。

## 12. 发布到世界市场

1. 在 GitHub 上新建一个**公开**仓库，把输出目录里的 `index.json`、`packs/`、`previews/` 提交上去。
2. 索引地址是 `https://raw.githubusercontent.com/<用户名>/<仓库名>/<分支名>/index.json`。
3. 别人在“世界 → 世界市场”的来源列表里添加这个地址，就能看到并安装你的世界。国内网络可以在同一页选 jsDelivr 加速。

建议在仓库的 README 里写明作者、内容提示和授权方式。

## 13. 更新世界

改完内容后，把 `pack.json` 的 `revision` 加 1，再运行一次打包命令。新版本会生成新的 zip（文件名带新版本号），`index.json` 里这个世界的条目会换成新版本。已经发布的旧 zip 不要改也不要删：安装过的人靠 sha256 核对文件，镜像也可能缓存旧文件。装过旧版本的人会在世界市场里看到“有更新”。

## 常见问题

| 报错或现象 | 原因和解决 |
|---|---|
| 职业的属性必须覆盖全部属性且合计等于 budget | 某个职业少了一项属性，或点数加起来不等于 `budget` |
| 职业的技能无效 | 技能 id 写错，或数量超过 `rules.skillSlots` |
| initial.links 只能引用公开条目 | 开场连到了 `public: false` 的条目 |
| presentation.json 用到了图片 xxx | `images/` 里缺这张图，补上或删掉对应的 `image` |
| 市场显示“编号冲突” | 对方有同 id 的自定义世界，换一个带前缀的 id |
| 市场显示“内容有变” | 同一个版本号发布了不同内容，请提升 `revision` |
| 故事后半段 AI 忘了结局 | 世界观、条目和结局总量超过 6000 字被截断，精简世界观 |
